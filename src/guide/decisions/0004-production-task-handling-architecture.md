Архитектура работы с производственными заданиями

 
## Контекст

Модуль **Production Tasks** отвечает за управление производственными заданиями (далее — ПЗ) внутри системы **SEP ERP Server**.  
ПЗ представляют собой список сущностей (сборок или металлообработки), которые необходимо выполнить назначенными пользователями в рамках производственного процесса.

Весь функционал реализован **внутри SEP ERP Server**, без выноса в отдельный микросервис. Логика сопряжена с данными заказов склада и ограничениями по объёмам производства.

## Структура производственного задания

Производственное задание является центральной сущностью и описывается моделью `ModelProductionTask`.  
К ПЗ привязываются конкретные производственные сущности — позиции задания, представленные моделью `ModelProductionOperationPos`.  
Каждая такая позиция, в свою очередь, содержит одну или несколько операций технологического процесса, описываемых моделью `ModelOperationPosition`.

Связи между сущностями:

- Одно **ПЗ** (`ModelProductionTask`) содержит **множество позиций** (`ModelProductionOperationPos`).
- Каждая **позиция** (`ModelProductionOperationPos`) содержит **множество операций ТП** (`ModelOperationPosition`).
- Операции ТП хранят информацию о назначенных пользователях и оборудовании.

Детали полей каждой модели доступны в соответствующих типах: `ModelProductionTask`, `ModelProductionOperationPos`, `ModelOperationPosition`.

## Основные компоненты

### 1. Production Tasks Service (`production-tasks.service.ts`)

- Является центральным компонентом модуля производственных заданий.
- Реализует полный жизненный цикл ПЗ:
  - Создание ПЗ заданного типа (металлообработка / сборка)
  - Добавление позиций (сущностей) в ПЗ
  - Списание ПЗ (частичное или полное)
  - Привязка оборудования к ПЗ
  - Получение ПЗ по пользователю
  - Получение списка всех ПЗ
  - Получение ПЗ по оборудованию
  - Формирование данных для онлайн-табло
- Обеспечивает соблюдение бизнес-правил:
  - **Ограничение по объёму:** невозможно назначить в ПЗ больше единиц сущности, чем разрешено заказом склада.
  - **Автоматическое списание:** при уменьшении объёма складского заказа избыточные позиции в ПЗ автоматически списываются.

### 2. Интеграция со заказами склада

- Производственные задания всегда ссылаются на конкретные заказы склада.
- При создании или обновлении ПЗ сервис запрашивает актуальные лимиты объёма по сущности из модуля заказов склада.
- При изменении заказа склада (уменьшение объёма) запускается фоновый процесс согласования ПЗ с новыми лимитами.

## Бизнес-правила

1. **Ограничение количества:**  
   количество сущности в ПЗ не может превышать количество, заказанное складом на эту сущность.

2. **Автоматическая корректировка:**  
   Если количество заказа склада уменьшается, ПЗ корректируется: избыточные единицы списываются, чтобы соблюсти правило №1.

3. **Назначение пользователей:**  
   Каждая операция ТП сущности в ПЗ должна быть назначена конкретному пользователю, что фиксируется в системе.

## Обоснование архитектурного решения

Модуль оставлен внутри SEP ERP Server по следующим причинам:

- Тесная зависимость от заказов склада и бизнес-логики ERP.
- Отсутствие потребности в использовании ПЗ вне контекста SEP ERP на текущем этапе.
- Сложность поддержки согласованности данных при выносе в отдельный сервис без значительного усложнения архитектуры.
