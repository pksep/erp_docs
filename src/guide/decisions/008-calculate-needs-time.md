Расчетная дата изготовления (`calculate_needs_time`)
 

## Назначение

`calculate_needs_time` — это дата, которая должна показывать, когда деталь, сборка или изделие будет готово для закрытия потребности.

Пользовательский смысл поля: "Когда эта сущность появится в производстве настолько, чтобы ее можно было использовать дальше?"

Это поле особенно важно для комплектации. Операция комплектации может начинаться только после того, как готовы нужные дочерние компоненты.

## Текущее состояние в коде

В моделях есть поле `calculate_needs_time` для:

- изделий;
- сборок;
- деталей.

В текущем найденном коде нет активного метода `setActualNeedsTime`, который автоматически пересчитывает и сохраняет это поле.

Также нет найденных присваиваний `calculate_needs_time` в сервисах сборок, деталей, изделий или металлообработки.

Значит, на текущую дату документации поле существует в данных, но автоматический производственный пересчет этого поля не реализован в активном коде так, как описывали ранние версии документа.

## Как поле используется

Главное найденное использование — расчет старта операций комплектации.

Для операции с типом `byDeficitChildren` система:

1. находит дочерние сборки и детали первого уровня;
2. смотрит их `calculate_needs_time`;
3. берет самую позднюю дату;
4. ставит ее как `start_time` операции комплектации.

Простыми словами: комплектация начинается тогда, когда готов самый поздний из нужных компонентов.

Если у дочерних компонентов нет заполненных дат `calculate_needs_time`, операция комплектации не получает расчетного старта из этого механизма.

## Что показывают экраны списков

В некоторых списках и карточках пользователю может показываться поле с похожим названием `calculateNeedsTime`.

Важно не путать:

- `calculate_needs_time` — поле в базе у изделия, сборки или детали;
- `calculateNeedsTime` в выдаче некоторых API — вычисляемое значение для отображения, часто основанное на последней операции и ее длительности.

В отображении система может посчитать дату "на лету":

```text
дата готовности = start_time последней операции + длительность последней операции
```

Такое значение помогает пользователю увидеть ориентир по конкретной производственной задаче, но само по себе не означает, что поле `calculate_needs_time` в базе было обновлено.

## Связь с комплектацией

Комплектация зависит от дочерних компонентов.

Если у сборки есть дочерние детали и сборки, система берет максимальный `calculate_needs_time` среди них.

Пример:

| Компонент | Расчетная готовность |
| --- | --- |
| Деталь A | 10 мая |
| Деталь B | 12 мая |
| Сборка C | 11 мая |

Операция комплектации может начаться 12 мая, потому что деталь B готова позже остальных.

Если дата у детали B пустая, она не сможет дать корректный вклад в этот расчет.

## Как раньше описывался расчет

В ранней версии документации были описаны два типа расчета:

- дефицитный расчет — поиск партии, которая закрывает дефицит;
- проекционный расчет — расчет по ближайшим или последним производственным партиям.

По текущему коду эти алгоритмы не найдены как активное сохранение `calculate_needs_time`.

Поэтому такие правила нельзя считать рабочим поведением системы без отдельной проверки или реализации.

## Что сейчас пересчитывает плановые даты

Актуальный каскад плановых сроков идет через `ActualTaskRelative`.

Он пересчитывает:

- `plan_ready_time`;
- `calculate_start_time`;
- дочерние элементы спецификации.

Этот каскад не обновляет `calculate_needs_time` найденным кодом.

## Что система не делает

Система сейчас не гарантирует автоматическое заполнение `calculate_needs_time` после изменения производственной задачи.

Система сейчас не запускает отдельный сохраненный расчет `calculate_needs_time` после `plan_ready_time`.

Система не может надежно поставить старт комплектации по готовности детей, если у детей нет заполненных `calculate_needs_time`.

## Что важно пользователю

Если в интерфейсе дата расчетной готовности показывается в списке, она может быть вычислена для отображения из операции.

Если операция комплектации должна рассчитываться от готовности детей, нужно убедиться, что у дочерних деталей и сборок заполнено именно поле `calculate_needs_time`.

Если это поле пустое, комплектация может не получить ожидаемую дату старта.

## Короткая памятка

| Вопрос | Ответ |
| --- | --- |
| Поле есть в базе? | Да, у изделий, сборок и деталей |
| Кто сейчас автоматически сохраняет его? | В найденном коде активного пересчета нет |
| Где оно важно? | В расчете старта комплектации `byDeficitChildren` |
| Что будет, если у детей даты пустые? | Комплектация не сможет получить старт по готовности детей |
| Можно ли путать с `calculateNeedsTime` в выдаче API? | Нет, это может быть временно вычисленное значение для отображения |
