  Архитектура работы с файлами

 

## Контекст

В проекте SEP ERP Server реализована система работы с файлами, которая включает загрузку, хранение и управление документами. Необходимо задокументировать архитектуру этой системы для лучшего понимания её работы всеми участниками проекта.

## Текущая архитектура

### Основные компоненты

1. **Documents Service**
   - Отвечает за бизнес-логику работы с документами
   - Управляет метаданными документов
   - Обрабатывает загрузку и скачивание файлов
   - Управляет версиями документов

2. **S3 Service**
   - Абстракция над S3-совместимым хранилищем (MinIO)
   - Обеспечивает сохранение и получение файлов
   - Управляет правами доступа к файлам

3. **Хранилища**
   - **S3 Storage (MinIO)** - хранит бинарные данные файлов
   - **PostgreSQL** - хранит метаданные документов

## Примеры использования

### Загрузка файла

1. Пользователь загружает файл через API
2. Documents Service валидирует файл
3. В базу данных сохраняются метаданные файла
4. Файл сохраняется в S3 хранилище (MinIO)

### Получение файла

1. Пользователь запрашивает файл
2. Documents Service получает метаданные файла из базы данных
3. Пользователю возвращается проксированный URL MinIO
4. Пользователь загружает файл напрямую из MinIO

## Особенности реализации

- Файлы хранятся с хешем в имени для предотвращения дублирования
- Поддерживается версионность документов
- Реализована проверка прав доступа к файлам
- Используется кеширование для часто запрашиваемых файлов
